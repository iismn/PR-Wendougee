# Mac에서 이어서 작업하기

Wendougee LITA는 GeeFlow의 Kotlin Multiplatform/Compose 기반 UI 포크입니다. iPad 가로 홈은 원형 프로파일, 왼쪽 목록, 오른쪽 추출 그래프와 중앙 하단의 통합 조작부로 구성됩니다.

## 로컬 iOS 실행

```sh
git clone https://github.com/iismn/PR-Wendougee.git
cd PR-Wendougee
open iosApp/iosApp.xcodeproj
```

Xcode 26 이상과 JDK 21을 설치합니다. Xcode에 맞는 macOS 버전은 [Apple 요구 사항](https://developer.apple.com/xcode/system-requirements/)을 확인하세요. Android 타깃도 포함하므로 Android Studio의 SDK Manager에서 Android SDK를 설치하고, 필요하면 저장소 루트의 `local.properties`에 `sdk.dir=/Users/사용자/Library/Android/sdk`를 지정합니다. `local.properties`는 커밋하지 않습니다.

Xcode의 **iosApp** 스킴에서 iPad Simulator를 선택하고 Run을 누릅니다. 공유 스킴을 저장소에 포함하므로 새 Mac에서도 같은 스킴을 사용할 수 있습니다. 이 포크의 설치용 IPA나 App Store 앱은 아직 배포하지 않았습니다.

### USB로 연결한 실제 iPad에 설치

1. Xcode를 한 번 실행해 초기 설정과 iOS 플랫폼 설치를 끝냅니다. **Xcode → Settings → Apple Accounts**에서 본인의 Apple 계정으로 로그인합니다.
2. iPad를 USB로 연결하고 잠금을 해제한 뒤 **이 컴퓨터를 신뢰**를 승인합니다. Xcode의 **Window → Devices and Simulators**에서 페어링을 확인합니다.
3. iPad의 **설정 → 개인정보 보호 및 보안 → 개발자 모드**를 켜고 안내에 따라 재시동합니다.
4. Xcode의 **iosApp → Signing & Capabilities → Team**에서 본인 팀을 선택합니다. 또는 `iosApp/Configuration/Local.xcconfig.example`을 `Local.xcconfig`로 복사하고 `TEAM_ID`를 입력합니다. 개인 설정 파일은 Git에서 제외됩니다.
5. **iosApp** 스킴과 연결한 iPad를 선택하고 **Run**을 누릅니다.
6. 첫 실행에서 **신뢰하지 않는 개발자**가 표시되면 iPad의 **설정 → 일반 → VPN 및 기기 관리**에서 본인의 Apple Development 서명을 확인하고 신뢰를 승인합니다.

기본 앱 ID는 `com.iismn.wendougee.lita.debug`입니다. 이미 사용 중인 ID라는 오류가 나면 `Local.xcconfig`에서 `PRODUCT_BUNDLE_IDENTIFIER`를 고유한 값으로 지정합니다. 원본 GeeFlow의 앱 ID와 개발자 팀을 사용하지 않습니다.

터미널에서도 빌드·서명·설치·실행을 연속으로 진행할 수 있습니다.

```sh
bash scripts/run-ipad.sh --check
bash scripts/run-ipad.sh --list
bash scripts/run-ipad.sh --device '위에 표시된 iPad UDID' --team '본인 Team ID'
```

스크립트는 실제 기기용 `iosArm64` 앱을 빌드하고, 성공한 앱만 설치한 뒤 실행합니다. 설치 로그는 `.tooling/ipad-build.log`, 빌드 결과는 `build/ipad`에 저장합니다. 시뮬레이터용 앱은 실제 iPad에 설치할 수 없습니다.

무료 Personal Team의 설치용 프로비저닝 프로파일은 발급 후 7일에 만료됩니다. 이 제한 자체를 없앨 수는 없으며, 아래 자동 갱신으로 만료 전에 같은 앱을 업데이트 설치할 수 있습니다. [Apple의 개인 개발 계정 제한 안내](https://developer.apple.com/help/account/basics/about-your-developer-account)를 확인하세요.

### 무료 서명 자동 갱신

갱신 스크립트는 만료까지 72시간 이하이면 갱신을 시도합니다. **Mac에서 Xcode를 사용할 수 있고 신뢰한 iPad가 연결되어 있어야 합니다.** 갱신할 때 Wendougee LITA를 종료해 두세요. 실행 중이면 다음 시도로 미룹니다. Apple 로그인이나 macOS 서명 키 승인이 다시 필요하면 직접 완료합니다.

```sh
# 현재 승인한 빌드의 만료일과 소스 일치 여부
python3 scripts/refresh-ipad.py --check

# 만료가 가까우면 빌드·서명·업데이트 설치, 여유가 있으면 종료
python3 scripts/refresh-ipad.py --renew
```

새 소스를 테스트하고 iPad에 설치한 뒤 해당 빌드를 갱신 기준으로 등록합니다.

```sh
python3 scripts/refresh-ipad.py --approve-current-build --device 'iPad UDID'
```

갱신은 승인한 소스와 같은 앱 ID·서명 팀·기기를 사용하며, 앱을 삭제하거나 실행하지 않습니다. Apple에서 더 늦게 만료되는 프로파일을 발급한 경우에만 설치하고 새 만료일을 기록합니다. 소스가 바뀌었거나 기기가 연결되지 않았거나 앱이 사용 중이면 설치를 미룹니다. 해당 앱의 기존 프로파일만 `.tooling/ipad-renewal/profiles-*`에 백업하며 인증서나 비밀번호는 변경하지 않습니다. 상태와 로그는 `.tooling/ipad-renewal`에 저장하고 Git에 올리지 않습니다. 무료 서명은 Apple 서비스와 이 Mac의 연결 상태에 의존하므로 오프라인 상태에서 영구 실행을 보장하지는 않습니다.

### 기기 코드 직접 입력과 QR

기기 추가의 **코드 직접 입력**에서 QR에 들어 있는 전체 URL/JSON, 12자리 Bluetooth MAC 주소(콜론·하이픈 허용), MAC 주소로 끝나는 Wendougee/LITA Bluetooth 이름을 사용할 수 있습니다. 모델을 판별할 수 없으면 모델 선택을 표시하며, 기존 기기 제어 경고도 그대로 확인합니다. 임의의 일련번호나 짧은 숫자 코드는 Bluetooth 주소로 변환할 정보가 없어 등록하지 않습니다. iPad QR 카메라는 별도 UIKit 화면의 AVFoundation 촬영 세션을 사용합니다. 카메라 방향은 `AVCaptureDevice.RotationCoordinator`로 해당 iPad 센서와 미리보기에 맞춥니다. 이 iPad에서는 Xcode Device Hub의 화면 공유를 켠 동안 실제 카메라 영상도 검게 되는 현상을 확인했습니다. **More Actions → Stop Screen Sharing**으로 미러링을 끄고 QR 스캔을 다시 여세요. USB 빌드·설치와 서명 갱신에는 화면 미러링이 필요하지 않습니다.

`scripts/macos-env.sh`는 Xcode에서도 JDK 21과 SDK 위치를 찾도록 빌드 단계에 연결되어 있습니다. 이 Mac에 준비한 JDK는 `.tooling/jdk-21/Contents/Home`, Android SDK는 `.tooling/android-sdk`에 있으며 시스템 Java는 변경하지 않습니다. Gradle과 Kotlin/Native 캐시도 `.tooling` 아래에 유지합니다. 다른 Mac에서는 JDK 21을 설치하거나 `JAVA_HOME`을 지정합니다. 터미널에서 직접 Gradle을 실행할 때는 먼저 `source scripts/macos-env.sh`를 실행하세요.

실기기 설치 절차는 [Apple 기기 실행 안내](https://developer.apple.com/documentation/xcode/building-and-running-an-app)와 [개발자 모드 안내](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)를 따릅니다.

Windows에서는 Xcode/iOS 빌드를 할 수 없습니다. 이 저장소의 CI는 임시 Mac에서 Kotlin/Native 프레임워크와 iOS 앱을 함께 빌드하므로 첫 빌드가 오래 걸립니다. 로컬 Mac에서는 같은 작업 폴더, Gradle 캐시와 Xcode DerivedData를 유지하고 `clean`을 반복하지 마세요. UI 수정은 아래 JVM 렌더로 먼저 확인하고, UIKit 재질과 터치는 iPad에서 확인하면 됩니다.

## 빠른 UI 검토

```sh
./gradlew :desktopApp:run
./gradlew :shared:app:generateAllScreens
node scripts/preview-all-ui.cjs
```

`http://127.0.0.1:4182`에서 화면과 상태를 선택하고 낮·밤 또는 홈과 비교합니다. 재렌더링하면 갱신됩니다. 이 창에는 JVM에서 렌더링한 Compose 화면을 표시합니다.

특정 화면만 다시 캡처하려면 `./gradlew :shared:app:generateAllScreens -PreviewScenes=dashboard,profile-editor,step-editor,temperature,temperature-applying,free-control,free-control-flow,screensaver,welcome,welcome-profile`을 사용합니다. 목록은 `docs/UI-CATALOG.md`, 결과는 `docs/review/all-ui`에 있습니다.

## 한국어와 시간 연동

한국어 iPad에서는 UI가 자동으로 한국어로 표시됩니다. 다른 언어의 iPad에서는 설정 앱의 Wendougee LITA 언어를 한국어로 선택하세요. 앱의 **화면·테마 → 언어**에서도 시스템 설정으로 이동할 수 있습니다. Pretendard 네 가지 굵기는 앱에 포함됩니다.

**화면·테마 → 화면 모드 → 시간에 맞춰 자동**에서는 기기의 현지 시각에 따라 배경의 색과 밝기가 서서히 바뀝니다. 04:30부터 밝아져 아침 08:00에는 초록빛, 15:30에는 노을빛, 18:30에는 남색, 22:00부터 04:30까지는 검은색 배경을 표시합니다. 앱을 다시 열 때와 매 30초에 그 시각의 색을 계산합니다.

## 글자 크기와 전환

**설정 → 화면·테마 → 전체화면**은 iPad의 시계·날짜·배터리 상태 표시줄을 숨깁니다. 저장된 설정을 SwiftUI 호스팅 화면과 UIKit 루트에 전달하고, 앱으로 복귀할 때도 다시 적용합니다. 끄면 시스템 표시줄이 다시 나타납니다.

**설정 → 화면·테마 → 글자 크기**에서 100~160%로 조절합니다. 기본값은 120%이며 선택한 프로필에 저장됩니다. 시스템 글자 크기와 함께 적용되고 팝업에도 같은 배율을 사용합니다. 홈·온도·설정 화면은 160% 렌더도 확인할 수 있습니다.

```sh
source scripts/macos-env.sh
./gradlew :shared:app:generateAllScreens -PreviewScenes=dashboard,temperature,appearance -PreviewTextSize=160
```

홈의 기록은 홈의 원형 다이얼을 유지한 채 그 위에 표시합니다. 뒤의 다이얼 영역은 9dp 블러로 흐려지고, 기록창 오른쪽 위 닫기 버튼·창 밖 터치·가장자리 제스처로 닫으면 다시 선명해집니다. 기록 열기/닫기 동안 원형 다이얼과 네이티브 재질은 재생성하지 않습니다. 차트는 짧은 페이드로 전환하고, 일반 화면 이동과 뒤로가기는 240/200ms 페이드를 사용해 유리 재질의 위치를 프레임마다 움직이지 않습니다. 가장자리 제스처는 내비게이션의 전환 한 번으로 처리합니다. 빠른 온도 팝업은 확대·이동·페이드와 함께 뒤 화면이 흐려지고, 닫힐 때 역으로 복원됩니다. 온도 눈금은 터치·드래그할 때 눈금 선만 빛나고 손을 떼면 천천히 사라집니다. 드래그와 탭을 받으며 눈금을 조작하는 동안 팝업 스크롤이 가로채지 않습니다. 보일러가 꺼져 있어도 목표 온도를 미리 조절할 수 있으며, 적용 중에는 입력을 막고 머신에서 제공한 온도 값으로 맞춥니다. 실제 머신 반영은 기존 **확인** 버튼을 사용합니다.

## 화면 보호기와 홈 조작

**설정 → 화면·테마 → 화면 보호기**를 켜면 설정한 대기 시간 후 Dot 시계가 나타납니다. **Dot 시계 지금 시작**으로 바로 열 수도 있습니다. 같은 화면의 **Dot 시계 크기**는 60~200%이며 사용자별로 저장됩니다. AM/PM은 시계 바깥의 별도 영역에 표시하고 간격을 유지합니다. 시계를 터치하면 이전 화면으로 돌아오며, 화면 보호기를 사용하는 동안에는 자동 잠금보다 앱의 Dot 시계를 유지합니다.

홈의 압력·유량·추출 보일러·스팀 보일러 수치는 상단에서 화면 너비 전체를 사용합니다. 같은 크기의 유량·압력 계기는 그 아래에 배치하고 프로파일 목록의 너비와 높이를 줄였습니다. 오른쪽 추출 그래프 패널도 아래로 내렸습니다. 왼쪽 프로파일을 왼쪽으로 밀면 오른쪽에 빨간 X 삭제 버튼이 나타나고, 오른쪽으로 밀면 왼쪽에 초록색 연필 편집 버튼이 나타납니다. 버튼을 누르기 전에는 삭제·편집을 실행하지 않으며, 기본 연필 버튼과 길게 눌러 삭제하는 동작은 없습니다. X 버튼은 삭제 확인을 열고, 머신에 연결된 프로파일은 먼저 연결을 해제해야 삭제할 수 있습니다. 다른 화면에서 왼쪽 가장자리를 오른쪽으로 밀면 애니메이션과 함께 뒤로 돌아옵니다. 홈의 차트·기록에도 같은 제스처를 사용합니다.

머신 이름 아래의 작은 온도·압력 표시는 제거했고 사용자 사진 대신 웬두지 로고를 표시합니다. 홈 상단의 머신 이름은 로고와 같은 세로 중심에 맞추고 아래 방향 화살표를 표시하지 않습니다. 머신 이름과 상단 버튼에는 동일한 눌림 반응을 적용합니다. 머신 이름을 누르면 목록이 페이드와 짧은 슬라이드로 열리고, 뒤로 갈 때도 같은 전환을 적용합니다. 홈의 네이티브 유리 재질 위치는 전환 중 고정합니다. 보일러 빠른 설정·세척·저울 연결·블루투스 상태 순서로 기존 상단 행의 오른쪽에 하나의 그룹으로 배치합니다. 홈 독은 홈·그래프·기록·세로 바 자유추출·물 흘리기·설정·프로파일 추출/정지의 7개 원형 버튼을 같은 간격으로 배치합니다. 상단의 저울 아이콘은 전용 **저울 연결** 팝업을 엽니다. 하단 독의 톱니바퀴와 왼쪽 위 로고는 같은 **설정** 화면을 엽니다. 한 목록에서 보일러·패들, 세척·수위 알림, 저울·그라인더, 화면·테마, 단위·자동 연결, 사용자 프로필, 앱 정보를 선택합니다. 같은 배경 블러·전환을 사용하며 저울 사용 켜기, 다시 검색, 개별 연결·해제를 제공합니다. 팝업을 열고 닫는 것만으로 설정을 바꾸지 않으며, 연결 확인 중에는 중복 명령을 막고 실패하면 재시도할 수 있습니다. 그라인더는 설정의 **저울·그라인더**에서 관리합니다. 추출 시작은 재생 아이콘으로 구분합니다. 독과 다이얼 우측에는 온도 설정 바로가기가 없습니다. 온수를 지원하는 기기에는 온수 버튼도 표시합니다. 추출 또는 머신 사용 중에는 물 흘리기 버튼을 비활성화하고, 추출 중에는 마지막 버튼이 정지로 바뀝니다. 온도 설정은 상단의 설정 버튼에서 열 수 있으며 창 제목은 **온도조절**입니다. 그래프 화면의 홈 아이콘은 상단 버튼 그룹의 블루투스 바로 오른쪽에 통합되어 있고, 별도 겹친 버튼을 표시하지 않습니다. 독의 아이콘을 길게 누르면 기능 이름이 나타나고 아이콘이 살짝 떠오릅니다. 누른 채 좌우로 끌면 이웃 아이콘이 부드럽게 밀리며 자리를 만들고, 놓으면 새 위치에 고정됩니다. 변경한 순서는 사용자별로 저장되어 다시 열어도 유지됩니다. 지원하지 않는 온수 항목은 숨기되 저장된 위치는 유지하고, 알 수 없거나 중복된 저장 항목은 기본 순서로 보완합니다. 길게 누르기·드래그·짧은 쓸기·취소 동작은 물 흘리기나 추출을 실행하지 않습니다. 원래 기능은 움직이지 않은 짧은 탭으로만 실행합니다. 자유추출 하단의 각 버튼은 둥근 사각형 안에서 눌림 효과가 표시됩니다.

홈의 큰 원은 프로파일 편집으로 이동하지 않고 수동 추출 다이얼로 동작합니다. 시계 방향으로 돌리면 목표값이 증가하고 반대 방향이면 감소하며, 압력은 머신 범위 안에서 최대 12bar, 유량은 머신이 제공한 최대값으로 제한합니다. 정지 중 회전은 로컬 목표값만 변경합니다. 중앙의 배경 없는 재생 아이콘을 누르면 기존 자유추출 프로토콜로 수동 추출을 시작하고 실제 압력·유량 기록을 수집합니다. 추출 중에는 밝은 빨간 네모 정지 아이콘과 주변 발광을 표시하며, 다이얼 회전은 선택한 모드의 목표값을 전송합니다. 이 다이얼에서 시작한 추출이 끝났다는 확인을 받으면 레시피 이름·설명을 입력하는 팝업이 열립니다. 저장을 누르면 실제 추출 기록으로 새 레시피를 만들고 목록에 반영하며, 취소·닫기는 새 레시피를 만들지 않습니다. 이름이 비어 있거나 유효한 기록이 없으면 저장을 막고, 저장 실패 시 입력값을 유지해 다시 시도할 수 있습니다. 기존 추출 기록(히스토리)은 레시피 저장 여부와 독립적으로 유지합니다. 중간 시작 실패 시 정지 처리를 시도하고, 프로파일 추출·세척·연결 끊김 중에는 다이얼이 머신을 제어하지 않습니다. 중앙 목표 숫자는 소수점까지 Dot으로 표시하고 각 점 주변에 은은한 발광을 그립니다. 숫자 자체를 원의 가로·세로 중앙에 놓고 단위는 오른쪽에 별도로 배치합니다. 숫자 위에는 ‘수동 - 압력’ 또는 ‘수동 - 유량’ 한 줄만 표시합니다. 원을 누르고 돌릴 때 눈금 선만 밝아졌다가 서서히 꺼집니다. 우측은 넓은 곡선 레일이며 위쪽 게이지는 압력 우선, 아래쪽 물방울은 유량 우선입니다. 선택 부분은 전체 80° 원호의 절반인 40°를 사용하고, 레일 두께의 5%만큼 윤곽을 확장한 같은 원호 형태입니다. 별도 사각 유리판 없이 원 중심과 반지름을 공유하며 아이콘은 블러 위에 선명하게 표시합니다. 레일 자체를 별도 그래픽 레이어에 담고 선택창이 그 레이어를 블러 처리하므로, 원래의 선명한 레일이 겹쳐 보이지 않습니다. 선택창을 위아래로 끌면 잡은 지점의 상대 각도만큼 지연 없이 움직이고, 놓으면 압력(-20°) 또는 유량(+20°) 위치에 부드럽게 고정됩니다. 현재 프로토콜은 추출 중 제어기 전환을 지원하지 않으므로 모드는 정지 상태에서만 변경합니다.

빠른 머신관리는 불투명 패널과 배경 블러를 사용합니다. **세척시간 → 대기시간 → 반복횟수** 중 한 항목만 표시하고, 좌우 화살표로 순환하며 슬라이드·페이드로 전환합니다. 항목을 넘겨도 조절한 값은 유지합니다. 같은 배경 위에 이름, 빛 번짐이 있는 Dot 숫자, 눈금 순서로 표시합니다. Dot 숫자 크기는 42dp이고, 숫자·단위 아래에 여백을 두어 눈금과 하단 버튼이 한쪽에 몰리지 않도록 합니다. 가운데 기준선은 고정되고 눈금이 손가락을 따라 움직입니다. 왼쪽으로 밀면 값이 커지고 오른쪽으로 밀면 작아지며 Dot 숫자도 즉시 바뀝니다. 눈금은 조절 한계 밖에도 어둡게 이어서 그리고, 조절 가능한 범위와 양 끝 한계선은 더 밝게 표시합니다. 눈금을 누르거나 드래그하면 눈금 선만 빛나고 손을 떼면 서서히 사라집니다. 주변 배경에 퍼지는 광원과 보일러 곡선·선택점의 광원은 제거했습니다. 값은 계속 머신의 허용 범위로 제한되며 터치만으로 값이 뛰지 않습니다. 사용 안내와 세척 설명은 설정 왼쪽의 동그라미 느낌표 아이콘에서 확인합니다. 일상·정밀 세척의 입력은 각각 유지하고, **세척 시작**을 누를 때 선택한 프로그램을 저장하고 머신에 적용합니다. 세척이 시작되거나 진행 중이면 편집을 막습니다.

## 네이티브 Liquid Glass

`iosApp/iosApp/NativeGlassViewController.swift`가 UIKit 배경, `UIVisualEffectView`와 `UIGlassEffect`, 투명 Compose 전경을 관리합니다. iPadOS 26 이상은 실제 `UIGlassEffect`, 이전 버전은 `UIBlurEffect(.systemMaterial)`를 사용합니다. Compose 컴포넌트가 전달하는 창 좌표로 네이티브 재질의 위치를 맞추고, 다이얼 선택창은 Compose의 별도 레일 레이어를 직접 블러 처리하고, 선명한 원본 레일은 선택창 밖에만 그려 이중 경계를 방지합니다. 선택창은 레일 절반과 동일한 원호에 5% 윤곽 오프셋을 적용하며 아이콘을 마지막 전경에 표시합니다. 일반 원형·둥근 사각형은 UIGlassEffect를 유지하고, 별도의 사용자 정의 네이티브 재질이 필요하면 M/L/Q/Z 윤곽과 UIView 마스크를 지원합니다. 재질의 제거와 터치 상태도 전달합니다. 네이티브 유리 재질은 Compose의 화면·팝업 페이드와 같은 투명도를 따라갑니다. 팝업의 배경 블러 진행도는 UIKit에도 전달해 홈의 상단 버튼·큰 원·그래프 재질까지 함께 흐립니다. UIKit 재질 위와 Compose 전경 아래에 고정된 블러를 두고, 팝업이 닫히면 효과와 애니메이터를 완전히 해제합니다. 별도 팝업 창은 루트 UIKit 재질 호스트를 상속하지 않아 다른 창 좌표의 재질이 화면 모서리에 생기지 않도록 합니다. 화면 밖으로 이동할 때 원래 크기와 모서리를 유지하고 부모 영역에서 잘라, 뒤로가기 중 원형 재질이 변형되거나 이전 레이어가 남는 현상을 막습니다. 화면에서 제거한 재질 객체는 최대 12개까지 재사용해 홈 복귀 첫 프레임의 생성 부담을 줄이고, 메모리 경고 시 비웁니다.

빠른 온도 설정은 빠른 세척처럼 팝업으로 열립니다. 하나의 배경에서 추출·스팀 보일러를 함께 조절하며, 전체 추출 설정도 동일한 곡선 눈금 카드를 사용합니다. 머신에서 제공한 값으로 조절되고 기존 확인·저장 동작으로 적용됩니다.

Xcode의 **NativeReview** 스킴에서 iPad 시뮬레이터를 선택하고 Test를 실행하면 XCTest가 기기를 가로로 돌려 낮·밤 홈과 온도 화면을 캡처합니다. CI와 같은 파일을 추출하려면 다음 명령을 실행합니다.

```sh
xcodebuild -project iosApp/iosApp.xcodeproj -scheme NativeReview -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath build/ios-review build-for-testing CODE_SIGNING_ALLOWED=NO
bash scripts/capture-native-ipad.sh
```

`build/native-review`에는 PNG와 런타임 재질 객체 JSON, 소스 커밋이 저장됩니다. 스크립트는 iPadOS 26 이상, 가로 이미지 크기, 실제 `UIGlassEffect` 클래스 존재를 검사합니다. 캡처 진입점은 Debug 전용이며 GeeFlow의 데모 데이터로 실제 프로덕션 UI를 구성합니다.
